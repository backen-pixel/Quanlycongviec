## Findings and corrections

1. Campaigns were separated by ID in the backend, but React row keys still used campaign_name. Different IDs with the same label therefore collided. Use namespaced campaign IDs, a stable manual-label fallback, or a sorted ad-ID fallback. Display the campaign ID so equal labels are distinguishable.
2. The report callback had no stale-request guard. An older successful response could replace data for a newer selected company; an older failed response could erase newer results; older completion could stop the new loading indicator. Add a request-generation ref and ignore stale success/error/finally branches.
3. A new filter kept the previous summary visible and published a summary before its detail request succeeded. Clear the previous snapshot on load and publish summary/detail only after both reads succeed. Effect cleanup invalidates pending report work.

These are code/async-state findings, not observations from a running browser.
