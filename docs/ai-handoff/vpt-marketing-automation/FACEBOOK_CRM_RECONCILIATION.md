# Facebook–CRM reconciliation in the trial dashboard

2026-10-02. Baseline730c388. Risk HIGH: company isolation, source identity and status used for marketing decisions. This change brings the656 census into the existing saved-period dashboard; it does not assert exhaustive provider scope, CPQL or a release.

SQL657 adds a private STABLE inventory helper and replaces the trial snapshot definition so census metadata/items and CRM/quality/identity/spend are read in the same SQL statement. Only the latest run is selected, including failed/running runs; no fallback to earlier success. A scope revision or Page/token change marks the result stale. The helper has no direct service/browser execution grant; authenticated report authority is checked by the existing service and database entry point. Bounded arrays fail closed rather than truncate silently.

The backend compares every enumerated ID with its durable receipt and source proof, then checks an available CRM identity. It separately counts pending intake, review, missing receipt, conflicting proof, missing CRM, known in-window IDs omitted from enumeration, and acquisition times that cannot be proven. Reverse comparison uses provider acquisition time, not receipt delivery time. Known IDs after the scan watermark belong to a subsequent run. Deleted CRM or source-only evidence is retained as an exception. The public result contains counts and scoped exception receipt IDs; no contacts, provider IDs, proof bodies, scope tokens or credentials.

MATCHED_ENUMERATED means only the enumerated set agrees with current CRM evidence. Unknown retention, expired forms and undiscovered known forms remain issues. SCANNED does not prove that account permissions revealed every Page/form or all lead entrypoints. Actual CPQL and target attainment remain unavailable until complete measured coverage is verified. The remaining full goal includes that positive path, AI care/takeover, actual survey integration and wider-channel operational acceptance.

The UI shows scan interval, counts and exceptions, and can request recovery through the already default-off authenticated census endpoint. A dropped response retries the same requestUUID; controls lock during submission, late responses are fenced on unmount/company/trial change, and a retry survives a report refresh within the company. Start response includes server-derived company/trial IDs for verification. No client completeness flag is accepted. The UI does not enable any worker or provider permission.

Validation pending: isolated PG657 applied twice with real census/intake fixtures, reverse comparison, rights and simultaneous receipt mutation; independent review; full build; synthetic UI failures/retries/company switching. Rollback disables census writes/worker and removes the UI route when needed while retaining all receipt/census/CRM evidence. The additive read helper may stay installed. No real DB, token, budget, ad, message or trial is changed.
